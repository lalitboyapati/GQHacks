## 1. What data the strategy uses

There are **two independent pulls**. The notebook does **not** hit FIRMS on every Run All by default.

### A. Event list (when / which ticker to trade)

| Piece | Source | Where it lives |
|---|---|---|
| Disruption-like 8-Ks | Massive disclosures / 8-K text API | Built offline |
| Plant coordinates | `sites.json` + Nominatim geocode | Track data + `geocode_cache.json` |
| Thermal persistence | NASA FIRMS area API | Labels written into events JSON |
| Trade filter | `facility_group == brief` | In-notebook |

**Hand-off layout (preferred — same folder as the notebook):**

```
massive/gqh-massive-8k-starter/
├── <notebook>.ipynb
├── .env
└── disruption_events.json
```

**Also kept under the track** (source pipeline / tests):

`tracks/physical_facility_disruption/data/events/disruption_events.json`

Notebooks resolve events in order: **same-folder `disruption_events.json` → `data/events/` → track path**.

Each row is roughly: ticker, filing date, disruption type, site lat/lon, FIRMS anomaly fields, and `facility_group` (`brief` / `persistent` / `unknown`).

```python
USE_CACHED_EVENTS = True   # default: load the JSON, do not re-query FIRMS
REFRESH_EVENTS = False     # default: do not re-pull Massive 8-K text from the notebook
```

A normal Run All **reads the committed event file**, filters to `FACILITY_UNIVERSE` + study/OOS/holdout windows + `TRADE_GROUPS={"brief"}`, then attaches NYSE sessions `t_0` / `t_pre`.

### B. Option marks (P&L)

| Piece | Source | Where it lives |
|---|---|---|
| Option chains & daily bars | Massive OPRA REST | Fetched in-notebook |
| HTTP cache | Disk by URL hash | `massive/gqh-massive-8k-starter/.massive_cache/` |

For each brief event the notebook:

1. Pulls the chain as of `t_pre`
2. Picks ~1m / 2m / 3–6m expiries and ATM + OTM strikes
3. Marks legs through fixed horizons (`h = 1,2,3,5,10,21,…`) and expiry
4. Builds a synthetic spot from the ATM call/put pair (no separate equity feed)

First full run needs a live Massive key and can take several minutes; later runs reuse `.massive_cache/`.

### C. What FIRMS is *not* doing at notebook runtime

`FIRMS_MAP_KEY` is loaded for convenience, but with defaults above the notebook **does not call NASA**. FIRMS was already applied when `disruption_events.json` was generated. Judges can still re-label (see §4).

## 2. How `disruption_events.json` was pulled (for recreation)

This file is **not** hand-curated row-by-row. It was generated by the track fetch script, then cleaned.

### Pipeline (what we ran)

1. **Massive 8-K / disclosure text** for an industrial ticker universe (steel, chem, refining, mining, packaging, etc.), filing dates from **2019-01-01** onward, up to **500** filings per ticker.
2. **Text filter** in `tracks/physical_facility_disruption/massive_disruptions.py` keeps filings whose language looks like a physical facility disruption (fire, explosion, outage, shutdown, force majeure, weather-related plant damage, etc.) and drops known false positives (Item 5.04 blackouts, Item 1.04 mine-safety boilerplate, risk-factor “possibility of curtailments…” language, etc.).
3. **Site coordinates** from `tracks/physical_facility_disruption/data/sites.json` when present; otherwise Nominatim geocode from filing text (cached in `geocode_cache.json`).
4. **NASA FIRMS** (`--firms`, source `VIIRS_SNPP_SP` for historical coverage): query hotspots near the site for ~`persist_days` (default 3) after the filing date.
5. **Label** `brief` / `persistent` / `unknown` via `facility_groups.py`.
6. **Write** JSON (`count`, `generated_at`, `events[...]`).
7. **Post-filter** with the same `is_disruption_text` rules after broadening the regex (raw pull briefly hit ~90 rows; cleaned panel used in the study is **45** events).

A copy of that cleaned JSON was placed under this starter folder so judges can run notebooks without hunting through `tracks/`.

## 3. One-time environment setup

From this folder (`massive/gqh-massive-8k-starter/`):

**Windows**

```powershell
powershell -ExecutionPolicy Bypass -File setup.ps1
```

**macOS / Linux**

```bash
./setup.sh
```

Then edit `.env` (created from `.env.example`):

```env
MASSIVE_API_KEY=...          # required for option marks / any event refresh
FIRMS_MAP_KEY=...            # only for refreshing events with --firms
FIRMS_SOURCE=VIIRS_SNPP_NRT  # or VIIRS_SNPP_SP for deeper history
FACILITY_PERSIST_DAYS=3
FACILITY_SITES=tracks/physical_facility_disruption/data/sites.json
```

Keys (no quotes/spaces):

- **Massive** — Discord / challenge key with options access  
- **FIRMS** — free map key: https://firms.modaps.eosdis.nasa.gov/api/map_key/

Open the notebook, select kernel **Python (Gator Quant Hacks .venv)**, Run All.  
Section 1 should print `API key loaded (ends xxxx)` and `Events path: .../gqh-massive-8k-starter/disruption_events.json`.

## 4. How a judge should test

### Reproduce the reported study (fastest)

1. Leave `USE_CACHED_EVENTS = True`, `REFRESH_EVENTS = False`.
2. Confirm local file exists: `disruption_events.json` next to the notebook (~45 events).
3. Run All on `physical-facility-disruption-condor-plus-sweep.ipynb`.
4. Check in-sample / OOS counts, drop reasons, scoreboard, placebo ranking, OOS sign table, cost haircut.

Expected shape (order of magnitude): ~45 cached events, ~24 brief in-sample after filters, fewer after option-liquidity drops; OOS 2025 is small.

### Challenge the sealed holdout

```python
RUN_HOLDOUT = True
HOLDOUT_START, HOLDOUT_END = "2026-01-01", "2026-06-30"  # judges may change these
```

Re-run. Dates outside available OPRA history simply drop.

### Wipe option cache (force Massive refetches)

Delete `.massive_cache/` in this folder and Run All again.

## 5. Knobs that change the datapoints

| Knob | Effect |
|---|---|
| `FACILITY_UNIVERSE` | Which tickers are eligible |
| `TRADE_GROUPS` | Default `{"brief"}` — only FIRMS-brief events trade |
| `PERSIST_DAYS` | Brief vs persistent threshold (default 3) |
| `STUDY_*` / `OOS_*` / `HOLDOUT_*` | Time splits |
| `ENTRY` | `"post"` (filing close) vs `"pre"` |
| `BASELINE_BUCKET` / `EXPIRY_BUCKETS` | Which option maturity |
| `OTM_PCT` / `OTM_GRID` | Strike grid for pricing |
| `STRUCTURES` | Which P&L columns hit the scoreboard |
| `RUN_PLACEBO` / `N_PLACEBO` | Ordinary-day control sample |
| `MAX_EVENTS` | Cap for smoke tests |

## 6. Troubleshooting

| Symptom | Fix |
|---|---|
| Prompted for API key | Fill `MASSIVE_API_KEY` in this folder’s `.env` |
| `EVENTS_PATH ... exists=False` | Put `disruption_events.json` in the same folder as the notebook |
| 0 priced events | Thin options / dates past last OPRA session; inspect drop-reason table |
| Want FIRMS live | Re-run `fetch_disruption_events.py --firms`, then copy JSON next to the notebook |
| Slow iteration | `RUN_PLACEBO = False` while exploring |
| Kernel / imports | Re-run setup; pick **Python (Gator Quant Hacks .venv)** |

Keep `.env` out of submissions; it is gitignored.
